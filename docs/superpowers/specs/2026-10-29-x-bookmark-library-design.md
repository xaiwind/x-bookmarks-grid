# X 收藏本地资料库设计

## 目标与范围

在现有 Chrome MV3 扩展中建立可管理的本地收藏库，首期完成：

1. 导入时展示进度、新增/重复/失败数量和保存内容范围；失败项可重试，帖子按 X status ID 去重。
2. 在管理页全文搜索，并按作者、收藏时间范围、是否包含外链筛选。
3. 收藏可加入一个或多个项目，并记录备注、收藏原因、使用用途。
4. 多选收藏并导出为一个 Markdown 文件，包含正文、作者、原帖链接、时间及项目备注。

本期沿用用户已登录的 X 书签页作为数据源，不接 X API、不抓取外链文章全文、不下载媒体文件。默认采集帖子文字、作者、原帖 URL、发布时间、外链 URL 和图片 URL；保存范围在导入界面明确展示。AI 语义搜索、X 页面状态标记/取消收藏、定时后台同步单独立项。

插件 IndexedDB 是收藏资料库的主存储；Obsidian vault 是可选镜像。用户未选 vault 或 vault 权限不可用时，仍可导入和管理本地收藏。已选择 vault 时，成功导入的记录继续写入 Markdown 与现有索引文件；镜像失败单独报告，不回滚已保存的本地记录。

## 当前实现

这是原生 JavaScript ES modules 的 MV3 扩展。`extension/content.js` 滚动 X 书签页并解析帖子；`extension/popup.js` 分别执行 URL 索引和最多 10 条正文同步；`extension/manager.js` 渲染搜索和筛选；`extension/idb.js` 已用 IndexedDB 保存 Obsidian 目录句柄；`chrome.storage.local` 保存 settings、seen 和整个 records 数组。管理页当前已有关键词、分类、状态、最近同步时间筛选，但没有作者专用、外链筛选、项目、备注和选择导出。

## 方案与架构

扩展现有 IndexedDB 数据库版本，新增 `records`、`seen` 和 `projects` object store；帖子 ID 分别作为 records 与 seen 的主键，records 建立 author、createdAt 索引；保留 handles store。通过 `extension/bookmark-repository.js` 封装逐条读取、写入、删除、批量读取和迁移，UI 和同步逻辑不直接操作事务。settings 和少量同步状态继续保存在 `chrome.storage.local`；帖子正文、去重表和项目元数据保存在 IndexedDB，避免整库 JSON 写入和 `storage.local` 默认 10 MB 容量限制。每条记录以 `projectIds` 关联项目。

首次启动时检测旧版 `records`、`seen`。分别按 ID 幂等写入 IndexedDB，校验写入完成后再保存迁移版本标记；任何中断都可安全重跑。旧记录只在迁移确认后从 `chrome.storage.local` 删除。导入和同步通过 repository 查询 seen/record 状态，和 Obsidian vault 中的 `seen.json` 继续兼容；少量设置及同步摘要仍在 `chrome.storage.local`。

导入由已打开的 X 书签页发起。URL 索引阶段收集全部可见/可滚动到的收藏并逐条写入本地库；正文阶段沿用每批最多 10 条的限制。通过消息逐步报告扫描和保存状态，界面区分 URL-only 与正文已保存数量，并列出失败项。失败项可重新扫描/重试。重复 ID 更新已同步字段，不产生第二条记录；用户备注和项目关联在刷新采集字段时保留。页面关闭或连接中断时，已成功保存的记录保持可用，未完成项标为失败/待重试。

## 管理、编辑与导出

管理页增加作者、日期范围、含外链/不含外链控件，并在正文、标题、作者、URL、项目和用户备注中执行全文匹配。日期筛选优先使用原帖发布时间；旧记录缺少发布时间时使用导入时间。结果表支持单条或全选当前筛选结果。选中记录可批量加入项目并导出。记录详情编辑备注、收藏原因与用途，输入保存到对应 IndexedDB 记录。项目名称有稳定 ID，重命名不会丢失关联。

Markdown 导出为单个 `.md` 文件，每条收藏生成一节，列出标题、作者、原帖链接、发布时间、项目、正文、外链和图片 URL；备注、收藏原因、用途作为独立字段呈现。文件名使用 `x-bookmarks-YYYY-MM-DD.md`。导出仅下载用户选择的记录，不调用外部服务。

## 错误处理与隐私

逐条写入 IndexedDB，捕获配额、事务和解析错误并保留可重试 ID。重复导入幂等。迁移失败时不标记完成、不删除旧 chrome.storage 数据。X 登录失效或书签页不可访问时显示具体错误并保留现有资料。所有记录仅保存在当前浏览器配置的 IndexedDB；不上传帖子、备注或项目数据。

## 验收与测试

- 从旧版数据首次升级后，records 数量、正文、状态、文件路径及已有项目/备注（如有）均可读取；迁移重复执行不产生重复记录。
- 重复导入同一 status ID 不增加数量，并保留已有用户填写字段。
- 导入过程中数量持续更新；失败项能重试并在成功后从失败清单移除。
- 搜索正文、作者、原帖链接均能命中；作者、日期和含外链筛选可组合使用。
- 多选导出 Markdown 包含要求字段并正确转义 Markdown 特殊字符。
- 运行 `npm test`；补充 repository、迁移、筛选和导出单元测试；最后在 Chrome 中手工验证真实 X 登录页导入和页面交互。
